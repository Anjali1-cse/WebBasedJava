Types of Advices:
In case of Spring AOP, there are 5 types of advices.
1.Before Advice
2.After Returning Advice
3.After Throwing Advice
4.After Advice
5.Around Advice

Before Advice:
Used to define the functionality that is to be invoked before the execution of the target method.

After Returning Advice:
Used to define the functionality that is to be invoked after the successful execution of the target method.

After Throwing Advice:
Used to define the functionality that is to be invoked if the target method throws some exception.

After Advice:
Used to define the functionality that is to be invoked irrespective of whether the target method executes successfully or not.

Around Advice:
It is not a separate advice; rather it is a combination of all above 4 advices.

Implementing AOP in Spring:
In order to implement AOP using Spring, it is necessary to use a 3rd party library called as AspectJ.
The AspectJ provides relevant annotations for AOP:
1.@Aspect
2.@Before
3.@AfterReturning
4.@AfterThrowing
5.@After
6.@Around
7.@Pointcut

@Aspect:
It is to be applied at the class level to mark the class as an Aspect.


@Before:
It is to be applied at the method level to mark the method as a Before Advice.

@AfterReturning:
It is to be applied at the method level to mark the method as an After Returning Advice.

@AfterThrowing:
It is to be applied at the method level to mark the method as an After Throwing Advice.

@After:
It is to be applied at the method level to mark the method as an After Advice.

@Around:
It is to be applied at the method level to mark the method as an Around Advice.

@Pointcut:
It is to be applied at the method level to mark the method as a pointcut.
This method does not participate in execution; rather it is just used for forward referencing.

Enabling Proxy Generation:
Although Spring Framework is capable of generating proxy using a 3rd party library AspectJ, it is not possible unless the proxy generation support is enabled.
In order to do so, @EnableAspectJAutoProxy annotation is to be used.
It is to be applied at the class level of configuration specific class.

Getting Started with Spring AOP:
Install 3rd party library: AspectJ
Since Spring AOP works with AspectJ, it is necessary to install AspectJ specific libraries.
aspectjweaver
aspectjrt
Create a Target Class
This is the class for which an aspect is to be plugged-in.
It provides a method that is to be invoked by a client program.
Create an Aspect Class
This is the class that combines an advice and a pointcut.
An advice is configured using the relevant annotations.
E.g. @Before is used for Before Advice and @After is used for After Advice and so on.

In case of PointCut, the configuration is done using an expression that is called as PointCut Expression.
This PointCut expression is specified in the form of a qualified string.
E.g. the PointCut expression has several designators out of which the most commonly used is “execution”.
This expression can be used for every advice individually; however, it is not much recommended because if any further change is needed, it is necessary to change the expression for all types advices.
To resolve this problem, a marker method is used.
This method does not participate in execution; rather it is just used for forward referencing.	
Create a configuration specific class
This class is the configuration unit of the application.
Apart from bean declaration and component scanning, it needs to perform one more activity: Enabling the proxy generation support.
It is possible using @EnableAspectJAutoProxy.

Working with Around Advice:
It is an advice that combines all other 4 advices.
It defines a single public method that controls the entire workflow.
However, since the other private methods are to be invoked at different time intervals, there has to be proper demarcation about these method invocations.
E.g.
In between methods pertaining to Before and After Returning Advice, a control must be sent towards the target method.
This is possible using an interface: ProceedingJoinPoint.
It provides a method: proceed().
Since this public method handles Around Advice, it must be annotated with @Around annotation and refer to the PointCut expression.

Spring MVC:
Spring framework provides a separate module known as Spring MVC that is meant for developing web applications.



MVC:
MVC stands for Model-View-Controller.
It is a commonly used design pattern or an architecture for the development of web applications.

Model:
A model is responsible for handling business logic of the application.
It also maintains or stores application specific data.
Typically, it is implemented using simple Java classes (Java Beans) or even EJBs (Enterprise Java Beans).

View:
A view is responsible for handling presentation logic of the application.
Typically, it is implemented using HTML and JSPs.

Controller:
A controller is responsible for handling navigation and workflow.
It is used to bridge the gap between Model and View.
Typically, it is implemented using Servlets.

Types of MVC:
MVC architecture is mainly of 2 types:
1.MVC 1
2.MVC 2

MVC 1:
In this case, all the aspects, Model, View and Controller are handled using JSPs.
Since it leads to tight coupling, it is not recommended.
Since everything is taken care by JSP, it is called as Page Centric.

MVC 2:
In this case, all the aspects, Model, View and Controller are decoupled from each other.
Since all the aspects are separated from each other, it leads to loose coupling and therefore it is highly recommended.
Since the entire navigation is taken care by Servlet, it is called as Servlet Centric.

Spring MVC:
Spring MVC is based upon MVC 2 architecture and therefore it enforces standard practices.

Additionally, Spring MVC follows one more pattern: Front Controller.
It is a single servlet within the application that manages the entire navigation and workflow.
All the incoming requests to the application first hit this controller and then the further delegation takes place.
In case of Spring MVC, this front controller is predefined and it is named as DispatcherServlet.

Apart from Front Controller (DispatcherServlet), there are other components required in Spring MVC:
Controller
1.Model
2.View
3.View Resolver

Controller:
It is a component to which a request is delegated by a Front Controller for further processing.
It is implemented using a simple Java class annotated with @Controller annotation.
It returns the name of the view that is to be rendered.

Model:
It is a component that receives a request from Controller for further processing if the request processing is a heavy-weight activity.
It is implemented using a Java class.

View:
It is a component that is to be rendered to the user or it can accept data from user.
It is implemented using JSPs.

View Resolver:
It is a component used by Front Controller to resolve the view.
It is predefined and has several implementations.
The most commonly used is InternalResourceViewResolver.
