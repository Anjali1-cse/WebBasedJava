Performing Data Update:

In order to perform an update,
 it is first necessary to load the entity on which the update operation is required. This is done using the find() method.
Once the entity is loaded, its state can be modified at any time using setter methods. These changes affect the state of the entity but do not immediately update the database.
To complete the update operation and reflect the changes in the database, it is necessary to use commit the transactions.


Performing Data delete:

In order to perform an delete,
 it is first necessary to load the entity on which the delete operation is required. This is done using the find() method.
Once the entity is loaded, its can be deleted by remove methods. These changes affect the state of the entity but do not immediately delete the database.
To complete the delete operation and reflect the changes in the database, it is necessary to use commit the transactions.

Entity Persistence Life cycle:- 
 this life cycle of an entity consist of several stages and they are associted with a single object that is called
 as persistence context.
 Persistence context is object that is solely responsible for handling all the persistence related Operations(CURD).
 Eg.  in JDBC  it is java.sql.Connection whereas in hibernate it is org.hibernate.Session.
   there are four states involved
   1.Transient
   2.Persistent
   3.Detached
   4.Removed
1.Transient: when entity is not associted with the persistence context(Session) then it is said to be Transient state.
        eg:       Exam examObj = new Exam("102", "DBT", "theroy",60);
  At this time, the entity doesnot hava its own identity.

 2.Persistent: when an entity is associted with context(Session). then it is said to be Persistent state.
    this time, the entity has its  own identity.
          eg:       sessionObj.persist(examObj);// store the data
                    Exam foundExam=sessionObj.find(Exam.class, "103");

 3.Detached: if the persistence context(Session) with which an entity is associted getsClosed, then that 
             entity goes into detached state.   
        eg:   sessionObj.close();
		      factory.close();      

4.Removed: the entity goes removed state when the  removed.

Hibernate Query Language (HQL):
Since every ORM has its own query language, Hibernate provides HQL that allows to perform query operations on the DB table.

It is especially used while retrieving multiple records from the DB table.
Since RDBMS understands only SQL format, HQL in turn gets converted into SQL and further the query is fired on the DB.

Just like SQL, HQL provides several clauses out of which 2 are very frequently used.
1.FROM
2.SELECT

FROM:
It is the simplest form of HQL.
It populates a list of entity objects directly and hence processing becomes very easy.

In order to use HQL, Hibernate provides an interface: org.hibernate.query.Query.

To use this interface, it is necessary to obtain its reference.
It is possible using createQuery() method from Session interface.

Although, FROM clause is the simplest form of HQL, it has one drawback.
Since it loads the entire data of the object, if that data is not fully utilized, it leads to memory implications and therefore it is used only when the whole data is required.

Therefore, in case of loading specific data, SELECT clause is preferred.

SELECT:
It is used to select specific fields of an entity.
It populates a list of an array of type java.lang.Object due to which processing is little tricky.

Using Constructor Expression:
In order to simplify SELECT clause processing, Hibernate provides a special feature known as Constructor Expression.

It allows to instantiate a Java Bean using a parameterized constructor based upon the query string.
